# Issue Development

Develop the selected opportunity until the founder can approve the editorial direction before prose hides unresolved thinking.

## Develop only what the issue needs

Use `templates/issue-brief.md` as an optional working note, not a form. Link publication context rather than recopying it. Capture the reader/payoff, central claim, evidence and permissions, and argument shape in the evolving issue record. Add objections, overlap, commercial relationship, and reader action where consequential.

## Development conversation

Ask only questions that materially improve the brief. Prefer questions that resolve one of:

1. **Specificity:** What actually happened, to whom, under what conditions?
2. **Tension:** What was difficult, surprising, mistaken, or traded off?
3. **Mechanism:** Why did the result occur, and what is interpretation rather than observation?
4. **Transfer:** What can the reader use without assuming the founder's exact context?
5. **Limitation:** Where would this advice fail or stop applying?
6. **Evidence:** Which source supports the claim, and what remains unverified?

Do not conduct an interview for material the approved sources already answer.

## Structure selection

Choose structure based on the idea rather than habit.

- **Decision analysis:** situation → options → tradeoffs → decision → result → reader application.
- **Experiment:** question → setup → observation → interpretation → limitation → next test.
- **Mistake/lesson:** prior belief → evidence of failure → changed model → practical implication.
- **How-to:** reader situation → prerequisites → steps → checkpoints → failure modes.
- **Argument:** reader tension → claim → evidence → objections → bounded conclusion.
- **Case/example:** context → action → result → what transfers → what does not.

A personal opening is optional. Do not manufacture narrative drama.

## Claim map

For each material claim, attach:

- source ID;
- evidence strength;
- necessary qualification;
- unresolved verification or permission;
- intended location in the issue.

If the central claim lacks support, return to evidence gathering or narrow the claim. Do not draft around the gap.

## Direction and approval

When the founder has already authorized a specific direction and drafting scope, proceed within it; a second brief approval adds nothing. Otherwise show the compact direction and ask about the consequential choice. Preserve the actual request or approval verbatim in the issue record. Direction approval does not waive final draft approval, authorize durable memory, or permit an external mutation.

If the central claim lacks support, research or narrow the claim before drafting. A noncentral gap can remain clearly marked in a reviewable draft; use `references/editorial-review.md` before calling it publish-ready.
